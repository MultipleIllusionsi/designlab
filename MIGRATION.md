# Миграция галереи на CMS

Бриф для работы в Claude Code. Положи этот файл в корень проекта.

## Контекст

Проект: `ivi-design-lab` — Pinterest-подобная галерея (https://ivi-design-lab.vercel.app), хостится на Vercel.

Две страницы:
- **Главная** — сетка всех медиафайлов (изображения и видео), превью в маленьком размере
- **Детальная** — открывается по клику на карточку, медиа в максимальном качестве

Медиа лежит в Cloudinary. Размеры и качество задаются трансформациями прямо в URL — маленькие для сетки, большие для детальной страницы.

## Проблема

Список медиафайлов захардкожен в коде фронтенда. Чтобы добавить картинку, нужно:

1. Залить файл в Cloudinary
2. Вручную скопировать ссылку
3. Вставить её в массив в коде
4. Закоммитить и задеплоить

Следствия: пополнять галерею может только человек с доступом к репозиторию; порядок карточек меняется только правкой кода; заголовки и описания живут там же.

## Цель

Вынести каталог в CMS, чтобы:

1. Человек без доступа к коду мог добавлять медиа через админку
2. Порядок карточек менялся перетаскиванием мышью (например, поменять местами 5-е изображение и 8-е видео)
3. К каждому элементу можно было добавить заголовок и описание
4. Сохранились URL-трансформации размера и качества для изображений **и видео**
5. Новый элемент появлялся на сайте без редеплоя

## Архитектурное решение

Разделить два слоя:

- **CDN** (Cloudinary или ImageKit) — хранит байты, отдаёт трансформации через URL
- **CMS** (Sanity) — хранит каталог: какой ассет, в каком порядке, с какими текстами

Фронтенд берёт из CMS порядок и метаданные, из CDN — сами файлы.

### Почему Sanity

- Плагин `@sanity/orderable-document-list` даёт drag-and-drop сортировку документов прямо в списке админки. Работает через скрытое поле `orderRank`, которое читается из фронтенда через GROQ.
- Официальный плагин Cloudinary позволяет выбирать и загружать ассеты из медиабиблиотеки Cloudinary прямо внутри Sanity Studio — копипаст ссылок исчезает полностью.
- Бесплатный тариф покрывает задачу с большим запасом (лимиты уточнить на sanity.io/pricing — источники расходятся).
- Studio деплоится отдельно, редактор заходит по логину.

## Открытый вопрос: остаёмся ли на Cloudinary

**Решить до начала работы.** Зависит от доли видео в галерее.

У Cloudinary кредитная модель: 1 кредит = 1 ГБ хранилища, или 1 ГБ трафика, или 1000 трансформаций, или 500 секунд SD-видео / 250 секунд HD-обработки. На бесплатном плане 25 кредитов в месяц. Видео съедает их быстро, а следующий тариф — сразу $89/мес, промежуточного нет. При превышении квоты аккаунт могут заблокировать, а не выставить счёт за перерасход.

Альтернатива — **ImageKit**: единственный внятный конкурент по видео-трансформациям в URL (`/tr:w-300,h-300/video.mp4` — ресайз, кроп, обрезка, кадры-превью, адаптивный битрейт). Лимиты считаются по трафику, количество трансформаций не ограничено. Нюанс: первая трансформация видео обрабатывается не мгновенно, при неготовности может прилететь редирект на оригинал — лечится прогревом URL после загрузки.

Плагина-пикера для Sanity у ImageKit нет, понадобится кастомный input (~полдня).

**Правило:** если видео мало и они короткие — остаёмся на Cloudinary, миграция проще. Если видео много или планируется рост — сразу ImageKit, потом переезжать дороже.

## Модель данных

```js
// schemas/mediaItem.js
import { orderRankField, orderRankOrdering } from '@sanity/orderable-document-list'

export default {
  name: 'mediaItem',
  type: 'document',
  orderings: [orderRankOrdering],
  fields: [
    orderRankField({ type: 'mediaItem' }),
    { name: 'title',       type: 'string' },
    { name: 'description', type: 'text' },
    { name: 'asset',       type: 'cloudinary.asset' },
  ],
}
```

### Критично: хранить `public_id`, а не готовый URL

В CMS кладём `public_id`, `resource_type` (`image` / `video`), `width`, `height`. URL собираем в коде:

```js
const build = (id, transform) =>
  `https://res.cloudinary.com/${CLOUD_NAME}/image/upload/${transform}/${id}`

const grid   = build(id, 'f_auto,q_auto,w_500')
const detail = build(id, 'f_auto,q_auto:best,w_1600')
```

Иначе при смене размера превью придётся править каждую запись в CMS вместо одной строки в коде.

`width` и `height` нужны отдельно — для masonry-сетки, чтобы зарезервировать место под карточку до загрузки файла и убрать сдвиги layout.

## План работ

### 1. Разведка

Прочитать проект и зафиксировать:

- Стек и версии (`package.json`): Next.js или Vite/React — от этого зависит способ получения данных
- Где лежит захардкоженный массив медиа, какие у элементов поля
- Как построена сетка на главной, как устроен роутинг на детальную
- Где и как сейчас собираются URL Cloudinary, какие трансформации используются
- Сколько всего элементов и какая доля видео — нужно для решения по CDN выше

Схема CMS должна лечь на существующие поля компонентов, а не наоборот. Если в текущем массиве есть поля, о которых в этом брифе не сказано, — добавить их в схему.

### 2. Настройка Sanity

- Создать проект, поднять Studio (отдельная папка или монорепо — на усмотрение)
- Подключить `@sanity/orderable-document-list` и плагин Cloudinary
- Описать схему `mediaItem`
- Настроить CORS для домена сайта

### 3. Скрипт миграции

Одноразовый скрипт: берёт текущий захардкоженный массив → разбирает URL на `public_id` и трансформации → проставляет `orderRank` в текущем порядке → заливает документы в Sanity батчем.

Существующие файлы в Cloudinary перезаливать **не нужно** — они уже там, переносим только метаданные.

После прогона проверить: количество документов совпадает, порядок в Studio совпадает с текущим порядком на сайте.

### 4. Рефакторинг фронтенда

- Слой получения данных: GROQ-запрос с сортировкой по `orderRank`
- Хелпер сборки URL (см. выше), один на весь проект
- Компоненты сетки и детальной страницы переключить на данные из CMS
- Удалить захардкоженный массив — только после того, как всё заработало

### 5. Обновление без редеплоя

- **Next.js:** ISR + webhook из Sanity на `revalidate`. Новая карточка появляется через несколько секунд после публикации.
- **Vite/SPA:** фетч в рантайме с CDN-эндпоинта Sanity, ответ кэшируется на их стороне.

### 6. Оптимизация видео в сетке

Видео на главной не должно тянуть десятки мегабайт:

- Постер первым кадром: `so_0`
- Либо короткое зацикленное превью: `e_preview:duration_3`
- Ленивая загрузка самих роликов

## Ограничения

- Не коммитить токены Sanity и ключи Cloudinary в репозиторий — только переменные окружения
- Токен с правами записи нужен только скрипту миграции, фронтенду достаточно публичного read-доступа
- Не удалять захардкоженный массив до проверки работающей версии
- Сохранить текущий визуальный порядок карточек при миграции — это осознанная композиция, а не случайность

## Что должно получиться

Человек без доступа к коду заходит в Studio, жмёт «создать», выбирает файл из Cloudinary (или загружает новый), пишет заголовок и описание, публикует. Через несколько секунд карточка на сайте. Порядок меняется перетаскиванием.
